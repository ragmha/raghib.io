## Where the work moves

The first thing I notice about AI coding tools is how quickly they can produce
the routine parts of an implementation. The more useful question is what I do
with the attention that frees up.

## Pair Programming with Copilot

I use GitHub Copilot as a pair programmer. Not a replacement — a collaborator. The key is knowing when to accept suggestions and when to think deeper.

```python
import pandas as pd

def analyze_sales(filepath: str) -> dict:
    """Read sales data and return monthly totals by region."""
    df = pd.read_csv(filepath, parse_dates=["date"])
    return (
        df.groupby(["region", df["date"].dt.to_period("M")])["amount"]
        .sum()
        .to_dict()
    )
```

That saves typing, but it does not decide whether the calculation is right for
the business question. I still need to check the date handling, grouping and
meaning of the totals.

## The tools I reach for

I use GitHub Copilot for inline suggestions and chat-driven development. I use
Copilot CLI when I want help understanding a command, drafting a script or
investigating a build failure.

The boundary matters more than the tool name. A generated implementation is
still a proposal. I need to check how it fits the system before treating it as
finished, especially when it handles data, permissions or other sensitive work.

## What the code doesn't decide

The same shift shows up in a fetch helper. A generated implementation may
handle the HTTP response, but it cannot decide whether caching is safe for
this user, how credentials should refresh, or how retries interact with the
service's limits. Those choices need system context.

That is the part of AI-assisted development I want to understand better:
whether taking routine work off the keyboard lets us spend more time on
architecture, review and the assumptions behind a change.

I am also exploring where these tools help people understand an unfamiliar
codebase. Onboarding is one place where saving keystrokes is less important
than helping someone build a useful mental model.
